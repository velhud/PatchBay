# Live ordinary-Chat reliability repairs

Disposable coding trials exposed failures across worker completion, review
handoffs, Author edit rejection and Docker cancellation. These repairs follow
actual client and execution evidence rather than source-only checks.

## Resulting behavior

- Explicit structured Codex turn failures and recognized process failures take
  precedence over generic session completion. Unsupported model/account routes
  require correction before retrying the same selected worker. Ordinary report
  prose mentioning an error does not itself classify a successful turn as failed.
- Deterministic Author draft rejection finishes the operation with its original
  cause. Replaying a rejected key returns the preserved terminal failure; a
  corrected request requires a new key. Unknown execution keeps its existing
  recovery and fencing rules.
- Worker views and Hub projections use the same cleanup eligibility check as
  follow-up dispatch. A terminal job with a still-live executor is not message
  ready. The live evaluator checks actual dispatch acceptance before waiting
  for another turn.
- Portable process-marker discovery rechecks only PIDs whose separate process
  snapshots disagreed, with a bounded retry and fail-closed uncertainty.
- A local offline cleanup-recovery command records an explicit named-operator
  quiescence attestation after process, marker, group, server and lock checks.
  It never signals processes or rewrites the original supervisor proof.
- Unproven supervisor cleanup can write a private diagnostic containing only
  fixed reason codes. It does not change ownership or signalling authority.
- Peer review context identifies the retained candidate workspace and base
  revision. Read-only reviewers can inspect that candidate rather than mistake
  the unchanged source checkout for the implementation. Redaction preserves
  narrowly recognized numeric fencing SQL, mapping expressions and annotations
  while continuing to redact credential values, including quoted values with
  spaces.
- Author Docker execution concludes bounded `create` before deciding whether
  to start the acknowledged immutable container ID. Cancellation or deadline
  expiry after acknowledgement skips start and removes that exact container.
  Unacknowledged create effects remain unknown, even if a name query currently
  finds nothing. Private lifecycle records retain daemon and client identities;
  application stdout excludes Docker transport IDs.
- A Linux-only local Author operator command can release an exact unknown run's
  admission fence after explicit quiescence checks and attestation. It preserves
  the original unknown receipt, result and nullable error, adds a separate audit,
  and supports exact replay. It does not signal processes, remove containers,
  retry checks or expose a remote recovery tool. Incomplete identity evidence
  still blocks resolution.

## Runtime qualification boundaries

The complete official Codex CLI package is required, including execution hosts
and resources. Version and model-catalog success alone missed a missing shell
host in the live trial. A real read-only command must work before coding is
qualified for that installed account and exact model.

On macOS, ordinary successful coding turns can still encounter a short-lived
child identity race and correctly retain the cleanup fence. Available Darwin
process events cannot retrospectively rule out a detached child after that
identity is lost. Do not reinterpret this as successful cleanup or promise
unattended follow-ups from a passing coding test alone. Use the Linux execution
path when conclusive process cleanup is required; retain the Mac candidate and
original evidence when operator recovery is necessary.

Ordinary ChatGPT rendering is a separate boundary: some final answers failed to
display even in a no-plugin control, while tool execution and durable results
remained readable. Check canonical task/worker evidence rather than inferring
execution success or failure from an absent answer body.

## Evidence

The repaired Mac suite passed **1,220 tests with 39 platform skips**; the Linux
suite passed **1,253 tests with seven skips**. Compilation, ten explicit audit
regressions, the MCP evaluator (27 checks), its terminal-reconciliation variant
(38 checks), Hub/Edge and Hub V2 (32 checks) passed. The separate Mac Author
suite passed 172 tests with 35 platform skips. A subsequent local CLI guard
correction forwards `--expected-instance` to the existing store validation;
its focused resolution suite passed all 14 tests, and the Linux operator/CLI
follow-up passed 20 tests. The separate Linux Author suite passed 202 tests
with five skips. Eleven additional Linux execution/security tests passed with
the long-duration and pinned Docker image switches enabled, including the real
185-second run, offline network/credential/socket isolation and OOM handling.

Real ordinary-GPT-6 Extra High trials included concurrent Luna implementation
and read-only review, waits, named-worker follow-ups, review context, and a
review/repair cycle that found a Unicode edge case missed by the queue's 25
baseline tests. The independent reviewer verified the actual repaired candidate
and in-memory probes; the operator separately reran all 25 tests and SQLite/CLI
persistence probes. Author trials included multiple 21-test revisions in offline
Linux Docker, deterministic rejection/replay checks, a deliberately failing
candidate followed by exact-byte repair, historical receipt isolation, and
separate launch-time and running-command cancellations with proven cleanup.
The original old-runtime cancellation uncertainty remains in its immutable
historical receipt, with a separate operator disposition.
Preview-based integration then applied only the reviewed queue source file;
the operator verified exact source readback, unchanged protected files and Git
HEAD, the retained candidate worktree, and all 25 tests in the integrated
checkout. Author's final revision restored the original passing source bytes,
passed all 21 tests plus compilation, and left no active or uncertain execution.

Mac worker cleanup remained fenced as described above. Requirements evaluation
without supplied case receipts reports all 52 research cases `NOT_RUN`; this
does not replace or negate the separately retained live evidence. These results
do not qualify every research scenario, account/model, or production ingress.

Private capability endpoints, credentials, host paths, source fixtures and full
trial logs are deliberately kept outside the public repository. See
`QUICKSTART.md`, `TESTING.md` and `docs/authoring/operations.md` for the maintained
operating and verification contracts.
